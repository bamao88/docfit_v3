# real-core-v0 四阶段问题检查

日期：2026-06-16

## 这个文件是干嘛的

这个文件只回答一件事：现在的测试能不能把当前生成 Word 的问题，分别归到
模板解析、内容抽取、内容放置、Word 生成四个环节，并且把每个问题说具体。

它不是 9 个 Word 成品的验收结论，也不会改变 `real-core-v0` 当前的 `PASS`。
当前 `PASS` 只表示固定证据闭环已经跑通：输入事实已签收，输出文件能打开，
Word 页面图像证据也齐了。它不表示生成的论文已经符合学校格式。

本文件对应两个代码入口：

- `src/docfit/harness/product_quality.py`：读取一次真实转换产生的中间 JSON 和
  `final.docx`，整理四个环节各自暴露出来的问题。
- `tests/contract/test_real_core_four_stage_problem_checks.py`：用
  湖南农业大学模板和学生 003 源文档跑一次转换，然后确认四个环节都能给出
  具体问题说明。这里的 `tests/contract/` 是仓库现有测试目录名，意思是从外部
  行为检查系统，而不是只测某个私有函数。

验证命令：

```bash
uv run pytest tests/contract/test_real_core_four_stage_problem_checks.py -q
```

当前结果：测试通过。它证明“问题能被具体指出”，不证明“问题已经修好”。

## 为什么先做这层检查

`real-core-v0` 的固定证据检查已经能证明三件事：

- 真实学校模板和学生文档的基线事实已经签收；
- 转换流程的中间文件和最终 Word 文件都能生成；
- Microsoft Word 能打开这些文件并导出页面图像。

但它还不能证明这些产品问题：

- 模板里的说明文字和示例文字没有混进成品；
- 学生题名、摘要、关键词、正文、参考文献、致谢等内容进了学校模板的正确位置；
- 学生源文档里的旧封面、旧目录、旧模板说明没有被当成正文；
- Word 生成不是“复制整份模板，然后把学生内容追加到最后”。

所以这层检查的目标很窄：先确认四个环节都能把当前坏输出说清楚。只有先能
具体说清楚，后面才能把这些问题逐条改成正式检查规则。

## 当前选择的测试样例

```text
学校模板：hunannongye
学生文档：inputs/real-student-003-source.docx
临时输出：/tmp/real_core_product_quality_case
```

选择这个样例，是因为它一次就能暴露出四类问题：目标模板说明文字泄漏、
学生源文档前置页未处理、正文标题没有识别、学生内容都被放到同一个虚拟位置、
最终 Word 仍是追加写入。

## 四个环节现在能指出什么问题

### 1. 模板解析

这个环节应该做的事：

- 看懂学校模板里哪些部分是封面、声明、目录、题名、摘要、正文、参考文献、
  附录、致谢、手工表单；
- 看懂哪些文字只是模板说明或示例，不能进入最终成品。

当前测试能指出的具体问题：

- 湖南农业模板有 145 个非空段落，但解析结果里只有一个 `slot_body_start`。
  这说明程序没有形成“模板里有哪些目标位置”的结构清单。
- 解析结果里没有受保护区域，也没有必填字段。
- 模板第一个非空段落就是 `附件1 封面基本格式...`，但程序只是把它当普通
  模板段落记录下来。
- `（一号华文行楷空一行）`、`（一号黑体空一行）` 这类格式说明也没有被标成
  “不能输出到成品”的文字。

为什么这会导致坏输出：

如果模板解析不知道哪里是封面、摘要、正文等目标位置，也不知道哪些文字只是
说明文字，后面的步骤就只能复制模板文字，或者把学生内容粗暴追加到某个兜底位置。

下一步要做的正式检查：

- 模板解析结果必须列出学校模板的主要目标位置。
- 模板说明、示例、占位文字必须被标成“固定保留”“需要填写”或“不能进成品”。
- 如果一个真实学校模板最后只解析出 `slot_body_start` 这种兜底位置，这个环节
  要直接报告问题，不能让后续输出被当成产品质量合格。

### 2. 内容抽取

这个环节应该做的事：

- 从学生源文档里识别题名、摘要、关键词、正文标题、参考文献、附录、致谢；
- 把学生源文档自带的旧封面、旧目录、旧模板前置页当成源文档格式内容处理，
  不要当作要写进目标学校正文的学生内容。

当前测试能指出的具体问题：

- 这些正文标题仍然只是普通段落，没有被识别成标题：
  - `c_029: 1 前言`
  - `c_030: 1.1 研究背景与意义`
  - `c_032: 1.2 国内外研究进展`
  - `c_033: 1.2.1 磷肥应用现状`
  - `c_035: 1.2.2 磷肥施用对产量性状的影响`
- 这些源文档前置页内容仍然被当成普通学生内容：
  - `c_001: 湖 南 农 业 大 学`
  - `c_002: 全日制普通本科生毕业论文`
  - `c_005: 学生姓名：袁一文`
  - `c_006: 学    号：202240490218`
  - `c_007: 年级专业及班级：2022级种子（2）班`

为什么这会导致坏输出：

程序分不清“学生论文正文”和“学生源文档里的旧模板格式”，后面就会把旧封面、
旧目录、旧表单也当成学生内容写进目标学校模板。

下一步要做的正式检查：

- 内容抽取结果必须给标题、摘要、关键词、参考文献、附录、致谢等内容打上
  可检查的类型标记。
- 旧封面、旧目录、源文档格式说明必须有明确处理结果：丢弃、保留为证据、
  或等待人工判断，不能默认进正文。
- 如果真实学生文档里的明显标题仍然只是普通段落，这个环节要直接报告问题。

### 3. 内容放置

这个环节应该做的事：

- 把每段学生内容放到目标学校模板里的具体位置；
- 题名进题名区，摘要进摘要区，正文标题进正文结构，参考文献进参考文献区，
  致谢进致谢区；
- 不该进入成品的源文档格式内容，要给出明确的不写入原因。

当前测试能指出的具体问题：

- 当前 `124/124` 个写入动作都指向 `slot_body_start`。
- 具体例子：
  - `a_001 ['c_001'] -> slot_body_start text=湖 南 农 业 大 学`
  - `a_002 ['c_002'] -> slot_body_start text=全日制普通本科生毕业论文`
  - `a_003 ['c_003'] -> slot_body_start text=磷肥不同施肥量对米粉稻产量性状的影响研究`
  - `a_005 ['c_005'] -> slot_body_start text=学生姓名：袁一文`

为什么这会导致坏输出：

所有内容都进同一个兜底位置，就不可能得到目标学校要求的封面、摘要、正文、
参考文献、附录、致谢顺序。即使没有丢字，成品也不是“转换成目标学校格式”。

下一步要做的正式检查：

- 每个写入动作必须指向目标学校模板里的具体位置。
- 如果内容不写入，必须说明原因，例如旧目录、旧封面、手工表单、需要人工判断。
- 如果大部分内容仍然都指向 `slot_body_start`，这个环节要直接报告问题。

### 4. Word 生成

这个环节应该做的事：

- 最终 Word 只包含目标学校固定内容、应该保留的学生内容、以及按规则生成的内容；
- 模板说明、示例文字、占位提示不能出现在最终成品里；
- 学生内容要写到目标学校模板的对应位置，而不是追加到整份模板后面。

当前测试能指出的具体问题：

- 最终 Word 仍包含模板说明文字：
  - `docx paragraph 1: 附件1 封面基本格式...`
  - `docx paragraph 2: （一号华文行楷空一行）`
  - `docx paragraph 5: （一号黑体空一行）`
- 第一个写入学生内容的位置是 `word/document.xml:p[230]`。这是 Word 文件内部的
  段落编号；模板解析结果只有 145 个非空模板段落，所以这说明学生内容是在复制
  完模板后才开始追加。
- 最终输出的第一个非空段落仍是 `附件1 封面基本格式...`。

为什么这会导致坏输出：

用户看到的是“学校模板说明 + 学生论文附件”，不是一份已经套好目标学校格式的
论文。

下一步要做的正式检查：

- 最终 Word 里不能出现已知模板说明、示例文字、占位提示。
- 第一个学生内容不能出现在整份模板内容之后。
- Word 生成记录必须说明每段内容实际写到了哪个目标位置。

## 后续开发顺序

建议按这个顺序继续做：

1. 先修模板解析：让程序能列出学校模板的主要目标位置，并标出哪些模板文字
   不能进成品。
2. 再修内容抽取：让程序能识别学生文档里的标题、摘要、关键词、参考文献、
   致谢，也能识别旧封面、旧目录这类源文档格式内容。
3. 再修内容放置：让每段学生内容有目标学校位置，不能继续全部放到
   `slot_body_start`。
4. 最后修 Word 生成：清掉模板说明文字，把学生内容写到目标位置，然后重新生成
   9 个 Word 成品和页面图像证据。

这四步完成后，测试就不只是“能说出当前问题”，而是能在对应环节直接阻止同类
坏输出被当成成功结果。
