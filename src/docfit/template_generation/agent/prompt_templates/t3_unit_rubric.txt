$quality_goal
先把整个 T2 单元当作一个完整对象阅读：同时看单元截图、对象清单、表格行列结构、候选区域和相邻单元。t2_scope_label 和 T2 单元边界只限定本次事实范围，不预先决定任何 T3 policy。

先回答“这个单元整体是不是有价值、哪些结构必须完整保留、是否真的需要逐元素分析”，再选择成本最低且安全的 route：
- preserve_whole：整个单元都是有价值且同一保留语义，不再下钻；
- preserve_structure_classify_fields：正文/标签/表格骨架全部保护，只继续识别 fill/generated；
- inspect_suspected_regions：只深入明确列出的 source_seq 或 source_ref 对象，其余按默认策略保留；
- full_local_analysis：确有多种语义/变换交错时才完整下钻。

学校任务书、开题表、过程记录、答辩记录、成绩表、课题变更审批等行政表单，如果只有人工签署、手写意见和固定条款，且没有任何需要电子替换或系统生成的独立 raw run，才使用 preserve_whole + default_preservation_policy=fixed。只要对象清单或候选区域显示学生姓名、学号、论文题目、日期占位、示例值或其他可独立替换字段，就必须使用 preserve_structure_classify_fields，并把相关 source_seq/source_ref 放入 inspect 范围；固定标签和表格骨架仍受保护。正式声明正文保持 fixed，但其中独立的电子字段或纯格式批注仍应局部下钻。

目录单元的标题层级、引导点和示例页码是自动目录的整体生成骨架，不应作为 fixed 示例文字保留；优先 default_preservation_policy=generated，只下钻检查独立的字体字号/空行批注。最终模板需要根据真实正文标题重建目录。

错误删除比漏删更严重。正式声明、条款、标题、标签和有语义的填写指导不能因为出现“要求/说明/格式”等词就删除；只有后续能够精确绑定 raw run 的纯字体字号/排版批注才可能删除。不要逐元素输出 policy。
